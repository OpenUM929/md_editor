## 1. 문제 정의

- **증상** (사용자 원문, 2026-07-27): "제목의 경우에는 큰 글씨로 이를 만들어야 해 그래서 내가 H2로 설정을 하고 넘버링 단축키를 누르면 기존 설정의 크기로 다시 바뀌면서 넘버링이 만들어진다" — 즉, 단순히 번호가 추가되는 게 아니라, 방금 지정한 헤딩 레벨(H2, 큰 글씨)이 번호 매기기를 켜는 순간 **원래(더 작은) 크기로 되돌아가면서** 번호가 붙는다는 보고.
- **재현 조건** (사용자 보고, 아직 담당자 본인 재현 전): (a) 블록을 툴바 Heading select(`editor-toolbar.tsx:260-281`)에서 "Heading 2"로 지정 → (b) 곧바로 툴바 "번호 매기기" 토글(`editor-toolbar.tsx:387-393`, `ListTree` 아이콘) 클릭 → (c) 해당 블록이 축소된 크기로 렌더링되며 번호 prefix가 붙음.
- **관찰된 실패 산출물**: 에러 메시지·로그 없음 — UI 렌더링 결과에 대한 사용자 육안 보고만 존재. 에러 로그가 나올 수 없는 유형의 버그이므로, 본 계획서에서는 **§1.2 답변(태그 변경 여부)을 로그 대체 증거**로 삼는다.

## 2. 원인 분석

> ⛔ **원인 확정 게이트 미통과** — 아래는 코드 정적 분석만으로 도출한 **가설**이며, 재현·관측·반증이 모두 없다. 게이트(재현 + 범인 코드 줄의 실제 실행 관측 + 반증 실험) 통과 전까지 §3 수정 방안을 작성하거나 코드를 변경하지 않는다.

### 가설 A — `content` prop 재동기화 경합(setContent race)으로 헤딩 편집이 되돌려짐 → **정적 사실로 반증(기각)**

- **최초 근거**: `src/components/editor/tiptap-editor.tsx:220-230`의 `useEffect(() => {..., editor.commands.setContent(content), ...}, [editor, content])` — `content` prop이 오래된 값이면 문서 전체를 되돌릴 수 있다는 가설.
- **추가 검증(사실, 2026-07-27 재확인)**: `grep -rn "\.setContent\(|commands\.setContent" src/` 전수 검색 결과, 프로젝트 전체에서 `editor.commands.setContent(...)` 호출은 **정확히 3곳**뿐이다.
  1. `tiptap-editor.tsx:224` — `[editor, content]` 의존성 effect (위 가설의 대상)
  2. `doc-tab-content.tsx:171` — `handleRecoveryApply`(복구 다이얼로그 "적용" 버튼 전용)
  3. `doc-tab-content.tsx:188` — 복구 다이얼로그 "원본 유지" 버튼 전용
  2·3은 복구 다이얼로그 콜백에서만 호출되므로 번호 매기기 토글과 무관. 1은 의존성이 `content`(React state)이며, `handleHeadingNumberingChange`(`doc-tab-content.tsx:152-163`)는 **`content`를 전혀 변경하지 않고 `frontmatter`만 변경**하는 것을 코드로 확인했다(같은 파일 152-163줄, `setContent` 호출 없음).
- **결론**: 코드베이스에 존재하는 **모든** `setContent` 호출 지점을 전수 확인한 결과, 번호 매기기 토글 클릭에서 도달 가능한 경로가 **하나도 없다**. 가설 A는 "못 찾았다"가 아니라 "전수 조사로 경로 부재를 확인"했으므로 **기각**한다.

### 가설 B — CSS 특정도/캐스케이드 충돌로 h2 font-size가 다른 값으로 덮어써짐 → **정적 사실로 반증(기각)**

- **최초 근거**: `globals.css:169-219`의 `.heading-numbered ... h2` 규칙이 `report-theme.css`의 테마별 h2 font-size(15pt, `report-theme.css:52-53`)와 특정도 충돌을 일으킬 수 있다는 가설.
- **추가 검증(사실, 2026-07-27 재확인)**:
  - `globals.css:188-197`의 `.heading-numbered h2`/`h2::before` 규칙은 `counter-reset`/`counter-increment`/`content`만 선언하며 **`font-size`를 전혀 선언하지 않는다**(재확인 완료, 파일 전체 169-219줄 재열람).
  - `grep -n "font-size" src/app/*.css` 전수 검색 결과, h2의 font-size를 선언하는 곳은 `report-theme.css:53`(`.report-theme` 스코프, 15pt) 한 곳뿐이며 `.heading-numbered`와는 **다른 클래스 스코프**라 서로 값이 겹치지 않는다(같은 프로퍼티를 두 규칙이 동시에 선언해야 특정도 충돌이 발생하는데, 한쪽이 애초에 선언하지 않으므로 충돌 자체가 성립하지 않음).
  - `report-theme.css:11` 주석: "layout.tsx 에서 globals.css 다음에 import 하므로 동일 특정도에서 이 파일이 우선한다" — 이는 globals.css와 report-theme.css 사이 캐스케이드 순서 규약이 이미 존재하고 의도된 설계임을 보여준다(번호 매기기 관련 버그와 무관, 기존 설계).
- **결론**: CSS는 선언되지 않은 속성을 다른 규칙이 "제거"할 수 없다는 사양(spec)상 결과이므로, 이 두 파일의 관계만으로는 font-size가 바뀔 수 없다. 가설 B도 **기각**한다.

### 가설 D — 텍스트에 적용된 커스텀 `fontSize` 마크(TextStyle/FontSize)와 번호 prefix(`::before`)의 스타일 상속 차이 → **사실로 확정**

- **근거(사실)**: `editor-toolbar.tsx:224,397-402`에 별도의 "폰트 크기" 셀렉터가 있고, `editor.chain().focus().setFontSize(value).run()`으로 **선택한 텍스트에만** 적용되는 `textStyle` 마크(인라인 `<span style="font-size:...">`)를 사용한다(`tiptap-editor.tsx:19-20` `TextStyle`/`FontSize` 익스텐션). 이는 H1~H4 헤딩 레벨(블록 단위 시맨틱 태그)과 **완전히 별개의 메커니즘**이다.
- **확정(2026-07-27 사용자 확인)**: 요구사항 1.4 답이 Y로 확정됨 — 사용자가 실제로 "H2 지정 + 폰트 크기 셀렉터로 22pt/Bold 추가 지정" 시나리오를 사용했다.
- **정정**: 애초 우려("텍스트 자체가 줄어드는 것은 설명 못함")는 착시에 대한 재해석으로 해소된다 — 헤딩 **텍스트 자체는 줄어들지 않는다**. 번호 매기기를 켜는 순간 h2 기본 크기(작음)로 그려지는 **번호가 22pt 텍스트 바로 앞에 붙어**, 한 줄 안에 "작은 번호 + 큰 텍스트"가 섞여 보인다. 이걸 언뜻 보면 "제목이 작아졌다"로 인지하기 쉽다 — 실제로는 텍스트가 아니라 새로 붙은 번호만 작은 것이다.
- **Word와의 비교로 설계 의미 확인**: OOXML(Word)의 번호 서식은 `abstractNum > lvl > rPr`(수준 단위 고정 문자 서식) 또는 문단 시작 지점 서식을 따르며, 선택 영역에만 건 로컬 서식(direct formatting)은 따라가지 않는다 — 즉 Word에서도 텍스트만 드래그해 크기를 바꾸면 번호는 그대로 남는, 잘 알려진 동작이다. md_editor의 `::before` 방식이 이 Word의 실제 동작과 구조적으로 일치한다.

## 3. 수정 방안

번호(`::before`)가 텍스트와 항상 같은 크기·굵기로 보이려면, 폰트 크기를 "선택 영역에 거는 인라인 마크"가 아니라 **헤딩(h 태그) 자체의 서식**으로 지정해야 한다 — `::before`는 h 태그 자신의 computed style만 상속하기 때문이다.

기존 `custom-heading.ts`에 이미 `accentBorderColor`/`accentBorderWidth`(강조 바 색상/두께)가 헤딩 노드 속성 + 인라인 스타일로 구현되어 있어 동일 패턴을 그대로 재사용할 수 있다. `fontSize`/`bold`를 같은 방식의 노드 속성으로 추가하면:
- h 태그 자신에 `style="font-size:...; font-weight:..."`이 실림
- `::before`(번호)는 CSS 상속 규칙에 따라 **자동으로** 같은 값을 받음(추가 CSS 불필요)

부가로, 이 조사 중 `accentBorderColor`/`accentBorderWidth`가 저장 시 마크다운 변환(turndown)에서 **이미 유실되고 있었음**을 실측으로 발견했다(heading 전용 turndown 규칙 부재). 같은 수정에 이 왕복 보존 로직도 포함한다.
