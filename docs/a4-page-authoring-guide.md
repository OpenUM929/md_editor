# A4 페이지 구성 지침 (md_editor 문서 작성 규칙)

> 목적: md_editor에서 마크다운 문서가 **A4 용지 단위로 깔끔하게 나뉘어** 편집·인쇄·PDF에 동일하게 보이도록 하는 작성 규칙. rp_gen 표준양식(`MSYS_구축완료보고서.md` 등)을 md_editor로 옮길 때 페이지 구분이 깨지는 문제를 예방한다.

---

## 0. 왜 페이지 구분이 깨지나 (원인)

md_editor의 편집기는 **Tiptap(표준 마크다운/HTML 스키마)** 위에서 돈다. 페이지 분할은 다음 방식으로 이뤄진다(`src/hooks/use-auto-page-break.ts`, `src/lib/a4-margins.ts`):

1. **인쇄 가능 높이**를 계산한다 → `297mm − (상단여백 + 하단여백)`.
2. 편집 내용 전체 높이를 재서 `필요한 페이지 수`를 구한다.
3. **최상위 블록(문단·표·이미지·제목 등) *사이사이*에** 자동 페이지 나눔을 끼워 넣는다.

여기서 두 가지 구조적 제약이 페이지 깨짐의 근본 원인이다.

- **제약 A — 단일 블록은 쪼개지 못한다.** 자동 분할은 블록과 블록 *사이*에만 들어간다. 그래서 **한 개의 표/이미지/코드블록이 한 페이지 높이보다 크면**, 그 블록은 잘리지 못하고 흰 용지 밖으로 흘러넘친다(spill).
- **제약 B — 표준 마크다운만 인식한다.** Tiptap 스키마에 없는 마크업은 **저장/렌더 시 조용히 사라지거나 텍스트로 뭉개진다.** 사라진 요소는 높이 측정에서도 빠져 페이지 계산이 어긋난다.

`MSYS_구축완료보고서.md`가 md_editor에서 페이지가 안 맞는 이유가 정확히 이 둘이다: rp_gen 전용 HTML(제약 B)과 폭 900px 이미지·긴 표(제약 A)를 쓴다.

## 1. 절대 규칙 (지키지 않으면 페이지가 깨짐)

### 1-1. 페이지 나눔은 `---pb---` 토큰만 쓴다
- md_editor의 수동 페이지 나눔 마크다운 토큰은 **`---pb---`** 이다 (한 줄 단독, 위아래 빈 줄).
- ❌ rp_gen의 **`<div class="pagebreak"></div>` 는 인식되지 않는다.** Tiptap이 떨궈내므로 의도한 페이지 나눔이 통째로 사라진다.
- 편집기에서는 슬래시 명령/툴바의 “페이지 나눔”으로 삽입한다. 저장하면 `---pb---`로 왕복 보존된다.

```
...앞 페이지 내용...

---pb---

## 다음 페이지 첫 섹션
```

### 1-2. 문서 상단 인라인 `<style>` 블록을 넣지 않는다
- ❌ 문서 맨 위 `<style> ... </style>` 는 **떨궈진다.** md_editor는 문서마다 CSS를 심는 방식이 아니다.
- ✅ 대신 **프론트매터 `reportTheme`** 로 양식을 지정한다. (아래 2-1)

### 1-3. rp_gen 전용 HTML 블록을 표준 마크다운으로 바꾼다
Tiptap이 모르는 커스텀 HTML은 사라진다. 다음처럼 치환한다.

| rp_gen 마크업 | md_editor 표준 마크다운 | 결과 |
|------|------|------|
| `<div class="headline">결론</div>` | `> 결론` (문서의 **첫 인용문**) | one-paper 테마가 헤드라인 밴드로 렌더 |
| `<table class="kpi">…</table>` | 표준 4열 표 (`\| … \|`) | 테마 표로 렌더(요약 지표) |
| `<span class="att">붙임</span> **제목**` | `> **[붙임]** 제목` 또는 `**[붙임] 제목**` | 강조 라인 |
| `<div align="right">작성자</div>` | `**작성자**` (일반 라인) | 우측정렬은 생략 |
| `<p class="cap">※ 각주</p>` | `> ※ 각주` | 인용(주) 스타일 |
| 상단 `<style>…</style>` | 프론트매터 `reportTheme:` | 양식 테마 적용 |

> rp_gen의 headline·KPI·붙임 배지를 **픽셀 단위로 똑같이** 재현하려면 별도의 Tiptap 커스텀 노드가 필요하다(로드맵 4단계). 그 전까지는 위 표준 치환으로 “같은 양식 느낌”까지 낸다.

### 1-4. 이미지는 픽셀 폭 속성을 쓰지 않는다
- ❌ `<img src="..." width="900">` → 900px ≈ 238mm 로 **인쇄 가능 폭(기본 170mm)을 초과**해 옆으로 넘친다.
- ✅ 표준 마크다운 `![대체텍스트](경로)` 를 쓴다. 테마 CSS가 `max-width:100%` 로 폭에 맞춘다.

## 2. 페이지에 맞추는 구성 규칙

### 2-1. 프론트매터로 양식·페이지 모드를 정한다
```yaml
---
title: "문서 제목"
reportTheme: report        # report | meeting | proposal | technical | one-paper | plain
pageMode: bunri            # (기본) 여러 장을 A4 시트로 분리. 한 장짜리면 single
---
```
- **여러 장 보고서** → `reportTheme` 만 지정(페이지 모드는 기본 분리/bunri).
- **진짜 한 장 원페이퍼** → `pageMode: single` (내용 길이에 맞춘 한 장 시트).

### 2-2. 인쇄 가능 영역을 넘지 않게 “한 블록 ≤ 한 페이지”
여백 프리셋별 실측 인쇄 가능 영역(폭 × 높이):

| 여백 프리셋 | 여백 | 인쇄 가능 **높이** | 인쇄 가능 **폭** |
|------|------|------|------|
| 매우좁게(기본) | 20mm | **257mm** | 170mm |
| 좁게 | 30mm | 237mm | 150mm |
| 중간 | 40mm | 217mm | 130mm |

- **표·이미지·코드블록 하나가 위 ‘높이’를 넘지 않게** 만든다(제약 A). 넘으면 용지 밖으로 흐른다.
- 표가 한 페이지보다 길면 → **논리적 지점에서 여러 표로 나누고**, 각 조각의 **머리행(헤더)을 반복**해 준 뒤 사이에 `---pb---` 를 넣는다.
  ```
  | 장 | 제목 | 내용 |
  |:--:|------|------|
  | 6 | … | … |
  | 7 | … | … |

  ---pb---

  | 장 | 제목 | 내용 |
  |:--:|------|------|
  | 8 | … | … |
  ```

### 2-3. 큰 이미지는 한 페이지를 통째로 준다
- 거의 한 페이지 높이인 다이어그램/캡처는 **앞뒤에 `---pb---`** 를 넣어 **단독 페이지**로 배치한다. 측정·맞춤이 깨끗해진다.
- 이미지 실제 표시 높이가 인쇄 가능 높이보다 작도록 원본을 준비한다.

### 2-4. 제목(섹션)이 페이지 맨 아래에 홀로 남지 않게
- `##` 섹션 제목이 페이지 하단에 걸릴 것 같으면 그 **앞에 `---pb---`** 를 넣어 다음 장 상단에서 시작시킨다(고아 제목 방지).

### 2-5. 표는 열 수를 적정하게, 정렬 마커를 명시
- 테마 표는 `table-layout: fixed` 라 폭이 균등 분배된다. 열이 많으면 내용이 줄바꿈된다.
- 정렬은 구분선에 `:--:`(가운데) / `--:`(오른쪽) / `---`(왼쪽) 로 지정한다.

- [ ] 상단 `<style>` 블록 제거, 프론트매터 `reportTheme` 지정했나

## 부록: `MSYS_구축완료보고서.md`가 따르는 양식 (분석)

**결론: 한국 공공기관 표준 보고서 양식** — "앞 1~2장 요약(원페이퍼) + 뒤 상세 다(多)페이지" 구조. md_editor의 `reportTheme: report`(상세부) + `one-paper`(요약면)에 대응한다.

이 문서는 양식을 **문서 상단 인라인 `<style>` 블록에 자체 정의**해 두었다(md_editor는 이 방식을 미지원 → 프론트매터 `reportTheme`로 대체). `<style>`이 규정한 사양:

| 요소 | MSYS `<style>` 정의 | md_editor 표준 대응(§A) |
|------|--------------------|------------------------|
| 용지·여백 | A4, `margin: 20mm 18mm`, 본문 폭 174mm | A4, 여백 프리셋 20mm(매우좁게) |
| 본문 | 맑은 고딕 11pt / 행간 1.6 | 맑은 고딕 12pt / 1.9 |
| 제목박스 | `h1` 18pt 가운데 + 2px 테두리 | `# ` → 20pt 회색박스 |
| 섹션 | `h2` 13pt + 하단 실선 | `## ` → 15pt 좌측 강조선 |
| 소제목 | `h3` 11.5pt | `### ` → 13pt |
| 표 | 9.5pt, 헤더 `#eef1f5`, 고정폭 | 10.5pt, 헤더 `#F2F2F2`, 고정폭 |
| 참고(주) | `blockquote` 좌측 바 + 연회색 | `> ` 동일 |
| **헤드라인 결론** | `.headline` 14pt 가운데 + 상하 3px 밴드 | one-paper 첫 `>` 인용문 |
| **KPI 요약** | `table.kpi` (라벨/큰값/보조 3행) | 표준 4열 표 (카드형은 커스텀 노드 필요) |
| **붙임 배지** | `.att` 네이비 반전 뱃지 | `> **[붙임]** …` (뱃지형은 커스텀 노드 필요) |
| 캡션 | `.cap` 9pt 회색 | `> ※ …` |
| 페이지 나눔 | `<div class="pagebreak">` | `---pb---` |

### md_editor로 옮길 때 해야 하는 변환 (요약)
1. 상단 `<style>` 제거 → 프론트매터 `reportTheme: report`(또는 요약면은 `one-paper`).
2. `<div class="pagebreak">` → `---pb---` (§1-1), 그리고 **주제 경계에 맞춰** 배치(§2-4).
3. `<div class="headline">` → 첫 `>` 인용문 / `<table class="kpi">` → 표준 4열 표 / `.att`·`.cap`·`align` → §1-3 치환표.
4. `<img width="900">` → `![]()` (§1-4).
5. 각 섹션이 인쇄 가능 높이(기본 257mm) 안에 들어오도록 사이징, 넘치는 표는 헤더 반복해 분할(§2-2).

> **주의:** 헤드라인 밴드·KPI 카드·붙임 배지의 *픽셀 단위 재현*은 표준 마크다운으로는 근사까지만 되고, 완전 동일은 Tiptap 커스텀 노드가 필요하다(별도 과제). 본문·제목·표·개조식 등 **문서의 8할은 위 변환만으로 rp_gen과 동형**으로 나온다.
