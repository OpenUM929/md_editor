# A4 문서 작성 표준

> **이 문서는 정본(표준)이다.** md_editor 로 만드는 **모든 프로젝트의 매뉴얼·보고서 작성 표준**으로 삼는다.
> 구성은 두 부분이다.
>
> - **제1부 — 작성 규칙 (프로젝트 공통 표준).** 마크다운 문법·프론트매터·페이지 구성 규칙. 특정 프로젝트/구현에 의존하지 않는 이식형 규칙이다. 다른 프로젝트의 문서 작성자는 **제1부만 읽으면 된다.**
> - **제2부 — md_editor 구현 각주.** 위 규칙이 md_editor 안에서 어떤 엔진·파일·내보내기 경로로 실현되는지의 구현 세부. 도구를 고치거나 회귀를 진단할 때 참조한다.
>
> 목적: 마크다운 문서가 **A4 용지 단위로 깔끔하게 나뉘고, 한 페이지 = 하나의 완결된 주제**가 되도록 — **편집·인쇄·PDF·한글(HWPX)·워드(DOCX)** 다섯 표면에 일관되게 보이도록 한다.
>
> 대체 이력: `a4-page-authoring-guide.md`(작성 규칙) + `msys-report-a4-conversion-plan.md`(변환 절차) + 2026-07-21~22 세션에서 확정한 엔진 재설계·내보내기 확장을 본 문서로 통합한다.

# 제1부 — 작성 규칙 (프로젝트 공통 표준)

## 0. 핵심 원칙 (이 5줄이 전부다)

1. **한 페이지 = 하나의 완결된 주제.** 섹션(`##`)이 페이지 하단에서 시작해 다음 장으로 새지 않게 한다.
2. **자동 페이지 흐름을 신뢰한다. 주제 경계는 `---pb---`로 명시한다.** 엔진이 넘치는 블록을 다음 장 상단으로 알아서 밀어주므로(§제2부 A), 페이지가 흔들리지 않는다. `---pb---`는 "여기서 반드시 새 장을 시작하고 싶다"는 **주제 경계 선언**으로 쓴다(자동 나눔을 억지로 막기 위한 회피 수단이 아니다 — 그 불안정성은 엔진 차원에서 해소됐다).
3. **한 블록 ≤ 한 페이지** (인쇄 가능 높이 기본 257mm). 넘치는 표는 헤더 반복 분할, 큰 이미지는 단독 페이지. 단일 블록은 엔진이 쪼갤 수 없다(§2-1 제약 A).
4. **표준 마크다운만 사용.** 인라인 `<style>`·전용 HTML·픽셀 폭 이미지는 조용히 떨궈지거나 넘친다.
5. **양식은 프론트매터 `reportTheme`로 지정.** CSS가 그리고, 수정은 편집기가 그 자리에서 담당한다.

## 1. 표준 양식 사양 (기본기 — 이 값이 정본)

보고서 양식은 한국 공공기관 표준 보고서 양식 계열이다. **작성 시 이 사양을 기준으로 한다.**

### 1-1. 용지·여백
| 항목 | 값 |
|------|------|
| 용지 | A4 세로 (210 × 297mm) |
| 여백 프리셋 | 매우좁게 20mm(기본) · 좁게 30mm · 중간 40mm (상·하·좌·우 동일) |
| 인쇄 가능 폭 | 210 − 좌우여백 (기본 **170mm**) |
| 인쇄 가능 높이 | 297 − 상하여백 (기본 **257mm**) |
| 페이지 간격(분리 모드) | 8mm |

### 1-2. 타이포그래피 (reportTheme=report/기본)
| 요소 | 마크다운 | 크기 / 서식 |
|------|----------|-------------|
| 본문 | 일반 텍스트 | 맑은 고딕 12pt / 행간 1.9 / 검정 |
| 제목박스 | `# 제목` (h1) | 20pt Bold, 가운데, 회색 #F2F2F2 배경 + 테두리 |
| 섹션 | `## N. 제목` (h2) | 15pt Bold, 좌측 4pt 강조선(네이비 #1B1760) |
| 소제목 | `### 제목` (h3) | 13pt Bold |
| 세부 | `#### 제목` (h4) | 11.5pt Bold |
| 개조식 1단 | `- 항목` | □ 마커(네이비) |
| 개조식 2단 | 중첩 `  - 항목` | ○ 마커 |
| 표 | `\| … \|` | 헤더 #F2F2F2, 0.6pt 실선, 10.5pt, 고정폭(fixed) |
| 참고(주)·캡션 | `> 문장` | 좌측 3pt 바 + 연회색 배경 |
| 코드 | ` ``` ` | 9pt, 연회색 배경 |
| 이미지 | `![]()` | 폭 100% 자동 맞춤, 가운데 |

> ⚠️ **밀도 주의:** 본문 12pt·행간 1.9는 원저자 rp_gen 원본(11pt·1.6)보다 **페이지당 분량이 약 22% 적다.** 그래서 다른 도구의 페이지 경계를 그대로 옮기면 여기서 먼저 넘친다. 페이지 배치는 이 표준의 실측 기준(§3-2)으로 다시 잡는다.

### 1-3. 카테고리별 강조색 (reportTheme 값)
`report`=네이비 #1B1760 · `meeting`=청록 #0F766E(제목 밑줄형) · `proposal`=파랑 #1D4ED8(제목 반전 밴드) · `technical`=슬레이트 #334155(제목 좌측 바) · `one-paper`=네이비(첫 인용문을 헤드라인 밴드로) · `plain`=무양식(기본).

### 1-4. 원페이퍼(one-paper) 추가 규칙
- 프론트매터 `pageMode: single` → 한 장 연속 시트.
- **첫 번째 인용문(`>`)** 은 헤드라인 결론 밴드(상하 굵은 선, 가운데 14pt Bold)로 렌더 → 문서 맨 앞 결론 한 줄을 여기 둔다.

## 2. 절대 규칙 (지키지 않으면 페이지가 깨짐)

### 2-1. 왜 깨지나 (구조적 제약 2가지)
편집기는 **표준 마크다운/HTML 스키마** 위에서 돈다.
- **제약 A — 단일 블록은 쪼개지 못한다.** 페이지 흐름은 블록과 블록 *사이*에서만 나뉜다. **표/이미지/코드블록 하나가 한 페이지 높이보다 크면** 잘리지 못하고 용지 밖으로 넘친다(spill). → §3-2/§3-3 로 미리 나눈다.
- **제약 B — 표준 마크다운만 인식한다.** 스키마에 없는 마크업은 저장/렌더 시 **조용히 사라지거나 텍스트로 뭉개진다.** 사라진 요소는 높이 측정에서도 빠져 페이지 계산이 어긋난다.

### 2-2. 페이지 나눔은 `---pb---` 토큰만 쓴다
- 수동 페이지 나눔 토큰은 **`---pb---`** (한 줄 단독, 위아래 빈 줄).
- ❌ 전용 HTML `<div class="pagebreak"></div>` 는 **인식되지 않는다**(스키마가 떨궈냄).
- 편집기에서는 툴바의 "Page Break" 버튼으로 삽입 → 저장 시 `---pb---`로 왕복 보존.
- **언제 넣나:** 원칙 0-2 대로 자동 흐름을 기본 신뢰하되, ①`##` 섹션이 다음 장에서 깨끗이 시작하길 원할 때 ②붙임/부록처럼 논리적으로 새 장이어야 할 때 ③큰 이미지·표를 단독 페이지로 둘 때 명시한다.

### 2-3. 상단 인라인 `<style>` 금지 → 프론트매터 `reportTheme`
- ❌ 문서 맨 위 `<style>…</style>` 는 떨궈진다. 문서마다 CSS를 심지 않는다.
- ✅ 대신 프론트매터 `reportTheme:` 로 양식을 지정(§3-1).

### 2-4. 전용 HTML → 표준 마크다운 치환표 (정본)
다른 도구(rp_gen 등)에서 넘어온 문서를 변환할 때 쓴다.

| 전용 마크업 | 표준 마크다운 | 결과 |
|------|------|------|
| `<div class="headline">결론</div>` | `> 결론` (문서의 **첫 인용문**) | one-paper 테마가 헤드라인 밴드로 렌더 |
| `<table class="kpi">…</table>` | 표준 **4열 표** (`\| … \|`) | 테마 표로 렌더(요약 지표) |
| `<span class="att">붙임N</span> **제목**` | **`**[붙임N] 제목**`** (강조 라인) | 강조 문단 ※ 아래 주의 |
| `<div align="right">작성자</div>` | `**작성자**` (일반 라인) | 우측정렬은 생략 |
| `<p class="cap">※ 각주</p>` | **`> ※ 각주`** (인용/주 스타일) | 참고(주) 박스 |
| `<img src="…" width="900">` | `![대체텍스트](경로)` | 테마가 `max-width:100%`로 맞춤 |
| 상단 `<style>…</style>` | 프론트매터 `reportTheme:` | 양식 테마 적용 |

> **주의:** 붙임 배지는 **`**[붙임N] 제목**` 강조 라인**으로 치환한다(섹션 제목 `## 붙임N`이 아니라 강조 라벨로 본다).
> 헤드라인·KPI·붙임 배지의 *픽셀 단위 재현*은 표준 마크다운으로는 근사까지만 되고, 완전 동일은 편집기 커스텀 노드가 필요하다(§부록). 본문·제목·표·개조식 등 **문서의 8할은 위 치환만으로 동형**으로 나온다.

### 2-5. 이미지는 픽셀 폭 속성을 쓰지 않는다
- ❌ `width="900"` ≈ 238mm → 인쇄 가능 폭(기본 170mm) 초과, 옆으로 넘침.
- ✅ `![대체텍스트](경로)`. **이미지 파일이 실재하는지 반드시 확인**(없으면 높이 0 → 페이지 계산 어긋남).

### 2-6. 이미지 파일 배치 — 문서별 `img.<문서명>/` 폴더 (단일 규칙)
문서에 이미지를 첨부할 때는 **아래 하나의 규칙만** 쓴다. 공용 폴더(여러 문서가 섞이는 방식)는 **폐기**한다.

1. **폴더:** 문서 `X.md` 의 이미지는 같은 폴더의 **`img.X/`** (X = 확장자 제외 파일명) 하위에 저장한다.
   - 예: `MSYS_구축완료보고서.md` → `img.MSYS_구축완료보고서/fig1-boundary.png`
2. **참조:** 항상 **상대경로** `img.X/파일명.png` 로만 참조한다(절대경로·URL 금지).
3. **워크스페이스는 경로 입력(path mode)으로 연다.** — 이것이 규칙의 필수 전제다(엔진 근거는 §제2부 B-3).

> 한 이미지를 여러 문서가 공유해야 하면 각 문서의 `img.<문서명>/` 에 **각각 복사**한다(문서 격리 우선 — 이동·삭제가 깔끔). 용량보다 규칙 일관성을 택한다.

## 3. 페이지에 맞추는 구성 규칙

### 3-1. 프론트매터로 양식·페이지 모드를 정한다
```yaml
---
title: "문서 제목"
reportTheme: report        # report | meeting | proposal | technical | one-paper | plain
# pageMode: single         # (선택) 진짜 한 장 원페이퍼일 때만. 생략 시 여러 장 분리(bunri)
---
```
- **여러 장 보고서** → `reportTheme`만 지정(페이지 모드는 기본 분리/bunri).
- **진짜 한 장 원페이퍼** → `pageMode: single`.

### 3-2. "한 블록 ≤ 한 페이지" — 실측 인쇄 가능 영역
| 여백 프리셋 | 여백 | 인쇄 가능 **높이** | 인쇄 가능 **폭** |
|------|------|------|------|
| 매우좁게(기본) | 20mm | **257mm** | 170mm |
| 좁게 | 30mm | 237mm | 150mm |
| 중간 | 40mm | 217mm | 130mm |

- 표·이미지·코드블록 하나가 위 '높이'를 넘지 않게 만든다(제약 A).
- 표가 한 페이지보다 길면 → 논리적 지점에서 **여러 표로 나누고 머리행(헤더)을 반복**한 뒤 사이에 `---pb---`.

### 3-3. 큰 이미지는 한 페이지를 통째로 준다
- 거의 한 페이지 높이인 다이어그램/캡처는 **앞뒤에 `---pb---`** 로 단독 페이지 배치.
- 이미지가 여러 장 몰리는 페이지(예: 화면 캡처 4장)는 **1~2장/페이지**로 제한하거나, 묶음 유지 시 자동 흐름이 이미지 *사이*에서 나누도록 둔다(블록 경계라 깔끔).

### 3-4. 제목(섹션)이 페이지 맨 아래에 홀로 남지 않게
- `##` 섹션 제목이 페이지 하단에 걸릴 것 같으면 그 **앞에 `---pb---`** 를 넣어 다음 장 상단에서 시작(고아 제목 방지).
- 참고: 자동 흐름은 큰 블록을 통째로 다음 장으로 밀어내므로 제목+본문이 한 덩어리로 시작되도록 유도되지만, "이 섹션은 반드시 새 장에서"를 확정하려면 명시 `---pb---`가 가장 확실하다.

### 3-5. 개조식·표 세부
- `□`/`○` 문자를 직접 찍지 말고 **마크다운 목록**(`- 항목`, 중첩 `  - 항목`)을 쓴다. 테마가 □/○ 마커를 그린다. (문자를 직접 찍으면 항목마다 별개 블록이 되어 페이지 중간에서 쪼개지고, 마커가 이중으로 보일 수 있다.)
- 표 정렬은 구분선에 `:--:`(가운데)/`--:`(오른쪽)/`---`(왼쪽) 명시. 테마 표는 `table-layout: fixed`라 폭이 균등 분배된다.

## 4. 변환 절차 (기존 도구 문서 → 이 표준)

### 4-1. 전역 치환 (문서 전체 일괄) — §2-4 치환표대로
1. 상단 `<style>` 삭제 → 프론트매터 `reportTheme: report`.
2. `<div class="pagebreak">` → `---pb---` (주제 경계로 재배치 — 원본 위치 그대로가 아니라 §1-2 밀도 반영).
3. `<div align="right">` → `**작성자**` 일반 라인.
4. `<div class="headline">` → 첫 `>` 인용.
5. `<table class="kpi">` → 표준 4열 표.
6. `<span class="att">붙임N</span> **제목**` → `**[붙임N] 제목**`.
7. `<p class="cap">` → `> ※ …`.
8. `<img width="…">` → `![]()` (폭 제거, 파일 존재 확인).

### 4-2. `□`/`○` → 마크다운 목록 (§3-5)
`□ 내용` → `- 내용`, 중첩 `○` → `  - 내용`. 테마가 마커를 그린다.

### 4-3. 긴 표 분할 (§3-2) / 큰 이미지 단독 페이지 (§3-3)

### 4-4. 원본 보존
변환 전 원본을 **백업**한다(`*.style-backup.md` 등). 저장소가 git이 아니면 특히 필수. 원본 파일 덮어쓰기는 사용자 확인 후.

### 4-5. 실측 미세조정 (권장)
높이 추정은 이미지 크기·폰트 렌더로 흔들릴 수 있다. **분리 모드 화면으로 페이지별 주제 완결·넘침·공백을 보고 `---pb---` 위치를 조정**해 확정한다. (자동 흐름은 페이지를 흔들지 않으므로, 조정은 "주제 경계를 어디로 둘지" 판단에 집중된다.)

## 5. 작성/변환 체크리스트

- [ ] 프론트매터 `reportTheme` 지정, 상단 `<style>` 없음
- [ ] 주제 경계·붙임·단독 페이지에 `---pb---` (`<div class="pagebreak">` 잔재 0)
- [ ] `headline`/`kpi`/`att`/`cap`/`align` 를 §2-4 표대로 치환 (`att`→`**[붙임N]**`, `cap`→`> ※`)

# 제2부 — md_editor 구현 각주

> 제1부 규칙이 md_editor 안에서 어떻게 실현되는지의 구현 세부다. **도구를 고치거나 회귀를 진단할 때만** 필요하다. 문서 작성자는 읽지 않아도 된다.

## A. 페이지 흐름 엔진 — `src/hooks/use-page-flow.ts` (상태 비의존)

**⚠️ 이 절은 2026-07-22 재설계로 전면 교체됐다.** 이전 정본이 설명하던 `use-auto-page-break.ts`(콘텐츠 높이로 `pageBreak` 노드를 문서에 삽입/삭제) + `tiptap-editor.tsx`의 `useAlignManualBreaks`(`marginTop` 스냅)는 **폐기·삭제**됐다. 그 구조는 "1페이지를 고치면 3페이지가 흔들리는" 연쇄(문서를 계산 대상이자 반영 대상으로 동시에 삼던 순환)를 낳았다. 예전 지침이 "자동 나눔에 맡기지 말고 `---pb---`를 직접 넣어라"라고 회피를 권했던 이유가 이것이었다 — 지금은 엔진 차원에서 해소됐으므로 그 회피 논리는 **더 이상 유효하지 않다**(제1부 원칙 0-2 개정).

### 현재 엔진의 4대 성질 (`use-page-flow.ts:14-30` 주석과 동일)
1. **연속 단일 문서.** 편집 표면은 하나의 ProseMirror 문서다. 페이지는 뒤에 그려진 배경 격자일 뿐, 콘텐츠를 실제 상자에 가두지 않는다.
2. **문서(doc)를 절대 변경하지 않는다.** 페이지 배치는 **위젯 데코레이션**(뷰 전용 스페이서 `<div class="pageflow-spacer">`)으로만 넣는다. `setMeta(pageFlowKey, …)` 메타 트랜잭션이라 `docChanged=false` → tiptap `update`/자동저장/`onChange`가 발화하지 않는다. **문서 오염·자동저장 유발이 구조적으로 불가능.**
3. **상태 비의존(stateless) 재계산.** 매 측정마다 데코를 걷어내(자연 레이아웃) 처음부터 다시 계산한다. 입력(콘텐츠)이 같으면 출력(페이지 배치)도 항상 같다 → 연쇄 흔들림이 발생할 수 없다(참조 투명성). 제1부 §6 검증 #7 의 근거.
4. **경계를 넘는 블록만 밀어낸다.** 페이지 경계를 넘는 블록 앞에 그 높이만큼의 스페이서 위젯을 삽입해 다음 페이지 상단으로 밀어낸다(`use-page-flow.ts:96-130`). 페이지 수는 밀어낸 뒤의 최종 콘텐츠 높이에서 파생(`:134`).

### 자동 흐름 vs 수동 `---pb---`
- **자동 흐름:** 넘치는 블록을 다음 장 상단으로 스페이서로 밀어냄. 문서에 노드를 넣지 않는다(표시 전용). 큰 블록이 밀리면 그 위에 빈 공간이 생길 수 있으므로(자연스러운 결과), 주제 경계를 깔끔히 하려면 저자가 `---pb---`를 명시.
- **수동 `---pb---`:** 실제 `pageBreak` 노드(`attrs.auto=false`)로 문서에 남아 `markdown.ts`의 `---pb---` 토큰으로 왕복한다. 엔진은 이 노드를 만나면 이후 콘텐츠를 다음 페이지 상단으로 강제한다(`use-page-flow.ts:127-129`). 툴바 "Page Break" 버튼이 삽입(`editor-toolbar.tsx:378`).

### 페이지 모드 3종 (`page-mode.ts`, `tiptap-editor.tsx` 렌더 분기)
- **wide** : A4 아님. 자유 폭 편집. 데코 없음.
- **ilche** (`pageMode: single`) : 한 장 연속 시트. 데코 없음(`use-page-flow.ts:60` — bunri 아니면 데코 비움).
- **bunri** (기본) : 여러 A4 흰 용지로 분리. 스페이서 데코가 콘텐츠를 용지 격자(297+8mm)에 맞춰 흐르게 한다. 프론트매터에 `pageMode: single`이 없으면 무조건 bunri.

### ⚠️ 편집기 열린 채 파일 덮어쓰기 주의
외부(도구/스크립트)에서 `.md`를 고쳐도, **편집기에 그 파일이 열려 있으면 저장/자동복원이 옛 내용으로 되돌린다.** 외부에서 바꿨다면 **편집기 탭을 닫고 다시 열어야** 반영된다.

## B. 내보내기 파이프라인 (MD / PDF / HWPX / DOCX)

편집 정본은 마크다운(`.md`)이고, 그 위에서 4개 표면으로 내보낸다. 페이지네이션 책임 주체가 표면마다 다르다는 점이 핵심이다.

| 형식 | 트리거(툴바) | 파일·라우트 | 페이지 분할 책임 |
|------|------|------|------|
| **MD 저장** | 자동저장 + 저장 | `fs/server.ts` `writeMd`/`writeFile` | — (원본 소스) |
| **PDF/인쇄** | "PDF 저장"(`export-pdf` 이벤트, `editor-toolbar.tsx:468`) 또는 Ctrl+P | `tiptap-editor.tsx`가 `.print-pages` 준비 → 브라우저 네이티브 인쇄 | **화면과 동일한 공용 코어**(`page-flow-core.ts`) ✅ |
| **HWPX(한글)** | "HWPX(한글) 저장"(`onSaveHwpx`, `:477`) | `lib/hwpx-plan.ts`(marked→plan) + `scripts/hwpx_gen.py`(python-hwpx) + `api/export/hwpx/route.ts` | **한글 프로그램**이 처리 — `---pb---` → `PageBreak`만 심음 |
| **DOCX(워드)** | "Word(.docx) 저장"(`onSaveDocx`, `:486`) | `lib/docx-export.ts` + `api/export/docx/route.ts` | **Word 프로그램**이 처리 — `---pb---` → `PageBreak`만 심음 |

- **PDF/인쇄 = 화면과 같은 엔진(2026-07-22 통일).** 예전엔 PDF가 래스터(html2canvas)라 화면과 딴판이었다. 지금은 `editor.getHTML()`을 `.print-pages`에 넣고 **화면과 동일한 `page-flow-core.computePageFlow`** 로 페이지 경계를 계산해 자동 넘침 블록에 `break-before:page`를 찍고, `@page` 여백을 프리셋으로 주입한 뒤 **브라우저 네이티브 인쇄**로 벡터 A4 PDF("PDF로 저장")를 만든다. 화면=인쇄=PDF 동일. (수동 `---pb---`는 `.page-break--manual`이 CSS로 나눔.) 무대화상자 서버 PDF(헤드리스 Chrome)는 별개 확장으로 미도입.
- **HWPX/DOCX는 "엔진이 페이지를 몰라도 정확한" 사례다.** 대상 프로그램(한글/Word)이 페이지네이션을 대신 하므로 `---pb---`만 각 포맷 페이지나눔으로 변환한다. 두 포맷은 HTML/CSS 렌더러가 아니라 별도 빌더가 marked 토큰으로 재조립하므로 **양식(테마)은 근사 재현**이다(픽셀 동일 불가, 페이지 경계는 프로그램 소유).
- **DOCX 변환기(`docx-export.ts`) — §1-2 사양 반영(2026-07-22).** 문서 기본 서식을 **맑은 고딕 12pt·행간 1.9·검정**(`styles.default.document`)으로 두고, 제목박스(h1: 20pt Bold·가운데·회색 #F2F2F2 배경+사방 테두리), 섹션(h2: 15pt Bold·좌측 4pt 강조선=강조색), 소제목/세부(h3 13pt·h4 11.5pt Bold), 개조식(`reportBullet` 넘버링 □/○, 마커색=강조색), 표(고정폭 `TableLayoutType.FIXED`·헤더 #F2F2F2·10.5pt·얇은 실선), 참고/캡션(좌측 바+연회색 배경), 코드(9pt·연회색)를 `docx` API로 조립. `---pb---`→`PageBreak`. 크기 단위=하프포인트(12pt=24)·테두리=1/8pt(4pt=32)·간격=트윕. 진입점 `docx/dist/index.mjs`. `mdToDocxBlob`/`mdToDocxBuffer`. 검증(실측): 생성 docx 언집→`document.xml`/`numbering.xml`/`styles.xml`에 위 값 존재 확인.
- **HWPX 변환기 — ✅ 공인 라이브러리 `python-hwpx` 로 재작성(2026-07-22).** 과거 수제 OWPML(`hwpx-export.ts`+`a4-styles.ts`)은 비준수형이라 한글이 "파일 손상"으로 거부했다 → **폐기**. 지금은 **파싱은 Node(`lib/hwpx-plan.ts`, marked)에서** 하고(→ DOCX와 같은 토큰), **조립은 Python(`scripts/hwpx_gen.py`, `python-hwpx` builder `government_report` 프리셋)에서** 한다. 저장 직후 `validate_editor_open_safety`(스키마+editor-open 검증)를 돌려 **실패면 파일을 남기지 않고 에러 반환(fail-closed, 임시파일→검증→`os.replace`)**. 라우트(`api/export/hwpx/route.ts`)가 plan(JSON)을 stdin 으로 넘겨 `python` 을 `spawn`(경로모드=디스크 저장, FSA=바이너리 반환). 표(머리행 #F2F2F2 음영)·제목·개조식 □/○·굵게 반영. **전제: 앱 서버 환경에 Python 3.10+ 와 `pip install -r scripts/requirements.txt`(python-hwpx)** — 없으면 명확한 오류 안내(`HWPX_PYTHON` 로 인터프리터 지정 가능). 견고화: `{{ }}`(계산필드 오인)·h4~h6(제목 1~3단계 초과)·Windows cp949 경로 인코딩 방어(회귀가드).

### B-3. 저장 위치 표시·폴더 열기 & 경로 모드(path mode) 전제
- 저장 성공 시 토스트에 **저장 경로**를 표시한다. **경로 입력 모드**에서는 **[폴더 열기]** 버튼으로 탐색기에서 해당 파일을 선택해 연다(`fs-access.ts` `revealInFolder` → `fs/server.ts`가 win32 `explorer /select` / darwin `open -R` / linux `xdg-open`).
- **두 워크스페이스 모드:**
  - **경로 입력(path mode)** — `getRootPath()`가 절대경로를 반환. 서버 FS(`/api/fs`)로 읽고 쓴다. `revealInFolder` 가능, 상대경로 이미지(`/api/asset`)가 풀린다.
  - **폴더 선택(handle/FSA mode)** — 브라우저 `showDirectoryPicker`. `getRootPath()=null`. 샌드박스라 절대경로를 알 수 없어 폴더 열기 불가(토스트에 상대경로만), 상대경로 이미지가 `localhost/…`로 404.
- **그래서 §2-6 이미지 규칙의 전제가 "경로 입력으로 열기"다.** 이미지가 안 뜨면 대개 파일 문제가 아니라 **여는 방식(mode)** 문제 — 경로 입력으로 다시 열면 해결된다.
