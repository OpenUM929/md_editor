# 계획서 — `MSYS_구축완료보고서.md` A4 표준 변환

> 목적: `docs/a4-page-authoring-guide.md`(이하 **가이드**)에 맞춰 `md_docs/MSYS_구축완료보고서.md`를 **md_editor에서 A4 페이지 단위로 깔끔하게 나뉘고, 각 페이지가 하나의 완결된 주제**가 되도록 변환한다. 기획처 처장 관점의 "문서 기본기"를 기준으로 한다.

## 0. 원칙 (가이드 요약)

1. **한 페이지 = 하나의 완결된 주제.** 섹션(`##`)이 페이지 하단에서 시작해 다음 장으로 새지 않는다. 안 들어가면 통째로 다음 장으로 (가이드 §2-4).
2. **주제 경계마다 작성자가 `---pb---`를 명시**한다. 자동 나눔에 맡기지 않는다. (엔진 수정으로 자동 나눔은 이제 소스에 저장되지 않으므로, 수동 나눔이 유일한 정본 구조)
3. **한 블록 ≤ 한 페이지** (인쇄 가능 높이 기본 257mm). 넘치는 표는 헤더 반복하여 분할, 큰 이미지는 단독 페이지 (가이드 §2-2·2-3).
4. **표준 마크다운만 사용** — rp_gen 전용 HTML·인라인 `<style>`·픽셀 폭 이미지 제거 (가이드 §1).

### 2-A. 결정 필요 — 헤드라인/KPI 밴드 처리
- 헤드라인 밴드(상하 굵은 선)와 KPI 카드는 **one-paper 테마 전용 시각요소**다. 이 문서는 다페이지 정식 보고서이므로 `reportTheme: report`가 맞고, 그러면 헤드라인은 **일반 인용(주)**, KPI는 **일반 4열 표**로 렌더된다(밴드/카드 아님).
- 픽셀 단위 밴드·카드 재현을 원하면 → (a) 요약면만 별도 one-paper 문서로 분리하거나 (b) Tiptap 커스텀 노드 신설(별도 과제). **권장: 우선 report 테마로 통일**하고, 밴드/카드는 후속 과제로 둔다.

## 3. 세부 변환 규칙

### 3-1. 개조식(`□`/`○`) 처리
현재 문서는 `□`·`○` 문자를 **본문에 직접** 찍는다(예: `□ **대시보드** : …`). md_editor 표준은 **마크다운 목록**(`- 항목`)이 테마 CSS로 `□`/`○` 마커를 자동 생성한다(§A-2). 두 가지 선택:
- **(권장) 마크다운 목록으로 변환**: `□ 내용` → `- 내용`, 중첩은 `  - 내용`(→○). 테마가 마커를 그려 일관.
- (대안) `□` 문자를 그대로 두면 목록 마커가 이중(□ + 테마 □)으로 보일 수 있으니 지양.

### 3-2. 긴 표 분할 (§2-2)
한 페이지를 넘길 위험이 있는 표 → 논리적 지점에서 쪼개고 **머리행 반복** + 사이 `---pb---`:
- 붙임1 화면구성(13행), 9.1 기능구성(12행), 붙임2 대분류집계(13행) — 렌더 실측 후 필요 시 분할.

### 3-3. 이미지 (§1-4·2-3)
- 폭 속성 제거: `<img src="manual_images/x.png" width="900">` → `![설명](manual_images/x.png)`.
- 5장·9.2 등 **이미지가 많은 페이지는 이미지 1~2장/페이지**로 제한, 큰 다이어그램(경계도·생명주기·매핑)은 단독 배치 고려.
- 경로 주의: 이미지가 `md_docs/manual_images/…`에 실재하는지 확인(없으면 깨진 이미지 → 높이 0 → 페이지 계산 어긋남).

### 3-4. 붙임 배지 → 섹션 승격
`<span class="att">붙임1</span> **MSYS 화면구성 내역**` → `## 붙임1. MSYS 화면구성 내역` (h2 섹션으로). 목차·페이지 경계 관리가 쉬워진다.

## 4. 리스크 / 한계

1. **헤드라인 밴드·KPI 카드·붙임 배지**의 픽셀 재현은 표준 마크다운으로 근사까지만(2-A). 완전 동일은 커스텀 노드 필요.
2. **높이 추정의 부정확성** — 이미지 실제 크기·폰트 렌더에 따라 페이지 경계가 ±1장 흔들린다. **스크린샷 실측 후 `---pb---` 위치를 조정**해야 확정된다(현재 스크린샷 e2e 미확보 상태).
3. **이미지 부재 시** 높이 0으로 잡혀 페이지가 위로 당겨진다 → 실제 이미지 파일 존재 확인 필수.
4. 자동 나눔 소스 오염 문제는 엔진 수정(완료)으로 해소됐으나, **모드 전환(초기/일체/분리) 일관성**은 사용자 스크린샷으로 최종 확인 필요.

## 5. 작업 순서

1. **원본 보존** — 변환본을 새 파일 `md_docs/MSYS_구축완료보고서.a4.md`로 생성(원본 rp_gen 포맷은 그대로 둠). ※ 원본 덮어쓰기 여부는 사용자 확인.
2. 전역 변환(§1) 일괄 적용 + 프론트매터 삽입.
3. 페이지 배치(§2)대로 `---pb---`를 주제 경계에 배치.
4. 세부 변환(§3) 적용.
5. md_editor에서 열어 **분리 모드 스크린샷** → 페이지별 주제 완결·넘침·공백 점검 → `---pb---` 미세조정 (2회 내외 반복).
6. 인쇄(Ctrl+P) / PDF로 최종 A4 확인.
