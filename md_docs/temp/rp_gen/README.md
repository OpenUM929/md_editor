# rp_gen — 보고서 생성기

마크다운을 **A4 페이지로 나뉜 모습 그대로** 웹에서 미리보고, 고치고, PDF로 저장하는 도구.

---

## 1. 설계 원칙

> **미리보기와 PDF는 같은 렌더러로 만든다.**

레이아웃 엔진이 둘이면(예: 미리보기는 HTML, 출력은 reportlab) 반드시 어긋난다.
따라서 브라우저 하나로 통일한다.

```
마크다운 ──▶ HTML+CSS ──┬──▶ 화면 미리보기   (Chrome 렌더링)
                        └──▶ PDF            (같은 Chrome 의 print-to-pdf)
```

양식 수치는 `temp/report/보고서_표준양식_가이드.md`(1.pdf 실측)를 CSS로 옮긴다.

---

## 2. 프로그램 구성

```
temp/rp_gen/
├── app.py               Flask 서버 (문서 목록·읽기·저장·PDF 변환)
├── md_blocks.py         마크다운 → 블록 리스트 (블록 = 편집·분할 단위)
├── export_pdf.py        헤드리스 브라우저 호출 → PDF
├── templates/
│   └── index.html       2단 화면 (좌: 소스 / 우: A4 미리보기)
└── static/
    ├── report.css       1.pdf 표준양식 + @page A4
    ├── paginate.js      A4 페이지 분할 엔진
    └── app.js           편집·동기화·저장
```

### 모듈 책임

| 모듈 | 책임 | 핵심 |
|------|------|------|
| `md_blocks.py` | 마크다운을 **블록 단위**로 쪼갬 | 블록마다 원본 줄 범위를 기억 → 미리보기에서 고친 내용을 원본에 되돌려 쓸 수 있음 |
| `report.css` | 표준양식 재현 | 제목박스 22pt, 붙임배지 `#1B1760`, □ 15pt, 줄간격 27pt, 표헤더 `#F2F2F2` |
| `paginate.js` | 실제 높이를 **재서** A4로 자름 | 추정이 아니라 `getBoundingClientRect()` 측정 |
| `app.js` | 블록 클릭 → 인라인 편집 → 재렌더 | 원본은 항상 마크다운 |
| `export_pdf.py` | Chrome/Edge `--print-to-pdf` | 미리보기와 동일 HTML을 인쇄 |

### 페이지 분할 방식

```
1) 측정용 컨테이너(폭 = 본문폭 168mm)에 전 블록을 한 번 그린다
2) 각 블록 높이를 실측한다
3) 누적 높이가 본문높이(255mm)를 넘기 직전에 페이지를 끊는다
4) 표는 한 덩어리로 두지 않고 행 단위로 쪼개며, 넘어간 쪽에 헤더를 반복한다
5) 이미지가 남은 높이보다 크면 다음 쪽으로 넘긴다
```

## 3. 화면 구성

```
┌──────────────────────┬───────────────────────────────────┐
│  문서 선택 ▼          │   [1/13]  ← →   [PDF로 저장]      │
│  ─────────────────── │ ┌───────────────────────────────┐ │
│  마크다운 소스        │ │                               │ │
│  (textarea)          │ │      A4 1쪽 (실제 비율)        │ │
│                      │ │                               │ │
│  · 입력하면 즉시      │ │   블록 클릭 → 그 자리에서 편집  │ │
│    우측 재렌더        │ │                               │ │
│                      │ └───────────────────────────────┘ │
│                      │ ┌───────────────────────────────┐ │
│  [저장] [되돌리기]    │ │      A4 2쪽                    │ │
└──────────────────────┴───────────────────────────────────┘
```

**미리보기에서의 편집** — 블록을 클릭하면 그 블록의 *마크다운 원본*이 그 자리에서 열린다.
고치고 벗어나면 즉시 재렌더·재분할된다.

> HTML을 직접 편집(contenteditable)하지 않는 이유: HTML→마크다운 역변환은 손실이 커서
> 저장할 때마다 원본이 조금씩 망가진다. **마크다운을 항상 정본으로 유지**한다.

## 4. 개발 계획

| 단계 | 내용 | 완료 기준 |
|:--:|------|----------|
| 1 | `report.css` — 표준양식 + A4 페이지 박스 | 1.pdf와 나란히 놓고 제목·배지·표 스타일 일치 |
| 2 | `md_blocks.py` — 블록 분해 | 구축완료보고서가 블록으로 빠짐없이 분해됨 |
| 3 | 서버 + 화면 골격 | 문서를 열어 미리보기가 뜸 |
| 4 | `paginate.js` — A4 분할 | 쪽 경계에 표·이미지가 걸치지 않음 |
| 5 | 인라인 편집 + 저장 | 고친 내용이 원본 .md에 반영됨 |
| 6 | `export_pdf.py` | 저장된 PDF 쪽수 = 미리보기 쪽수 |
| 7 | 메뉴얼(3,744줄) 적용 | 성능 확인, 예외 구문 처리 |

### 검증

- **쪽수 일치** — 미리보기 쪽수와 PDF 쪽수가 같아야 한다. 다르면 CSS `@page` 여백 불일치.
- **왕복 무결성** — 편집 없이 열었다 저장했을 때 원본과 **바이트 단위 동일**해야 한다.
- **이미지 실존** — 깨진 참조는 화면에 붉게 표시.

## 5. 페이지 구분자 — 무엇을 인식하는가

### 강제 나눔 (아래 셋 중 아무거나)

| 구분자 | 비고 |
|--------|------|
| `<div class="pagebreak"></div>` | **현재 문서가 쓰는 방식.** 그대로 호환 |
| `<!-- pagebreak -->` | 마크다운 뷰어에서 안 보임 (권장) |
| `!newpage` | `temp/report/md_to_report.py` 와 동일 |

### 자동 나눔

위 구분자가 **없어도** 내용이 A4를 넘으면 자동으로 나뉜다. 강제 구분자는
"여기서 반드시 끊어라"는 뜻이지, 나눔의 유일한 수단이 아니다.

### 나눔 금지 (한 덩어리로 유지)

| 대상 | 동작 |
|------|------|
| 이미지 | 남은 높이보다 크면 통째로 다음 쪽 |
| 제목(`##`, `###`) | 바로 뒤 내용과 떨어지지 않음 |
| 표의 헤더 | 항상 본문 행과 같은 쪽. 표가 쪼개지면 헤더 반복 |

### 인식하지 않는 것

- `---` (수평선) — 마크다운 본래 의미로 쓰므로 나눔으로 보지 않는다
- 빈 줄 여러 개 — 문단 구분일 뿐
