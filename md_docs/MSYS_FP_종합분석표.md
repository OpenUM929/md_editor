## 3-1. 코드성 데이터 및 유지 트랜잭션 (13건)

**적용 기준**

- 코드성 데이터: 소수의 속성으로 구현되어 레코드가 제한적이며 사용자에 의한 변경이 거의 발생하지 않는 데이터, 하드코딩 되어도 무관한 데이터
- 식별규칙: **하나의 트랜잭션 기능은 하나 이상의 데이터 기능을 참조한다**
  → 코드성 데이터는 데이터 기능이 아니므로, 이를 단독 참조하는 트랜잭션은 식별규칙을 충족하지 못함

| 구분 | 대상 | 판정 사유 |
|------|------|----------|
| 데이터 | `tb_sts_cd_mst` (상태코드) | 코드·코드명·색상 등 소수 속성, 운영 중 변경 거의 없음 |
| 데이터 | `tb_icon` (아이콘) | 하드코딩 가능 데이터 |
| 데이터 | `tb_menu` (메뉴) | 메뉴 정보는 하드코딩과 동일하게 식별하지 않음 |
| 트랜잭션 | 아이콘 저장·삭제·표시전환·가져오기·목록조회·내보내기 (6건) | 참조 데이터기능 0개 |
| 트랜잭션 | 상태코드 동기화·저장·조회·색상조회 (4건) | 참조 데이터기능 0개 |

| 운영환경 호환성 | 수준1 — 운영환경 호환성에 대한 요구사항이 없다 | **0.94** |
| 보안성 | 수준3 — 3가지 보안 요구사항 포함<br>(시큐어코딩 · 개인정보보호 · 웹취약점점검) | **1.03** |

**종합 보정계수** = 1.2195 × 0.88 × 0.91 × 0.94 × 1.03 = **0.9455**

> 연계복잡성 0.88(타 기관·회사 시스템과의 연계 없음)은 **유지**합니다.
> 데이터 수집 파트는 동일 회사 조직이며, FP의 애플리케이션 경계와 연계복잡성의 기관 범위는 서로 다른 기준이므로 EIF 산정과 모순되지 않습니다.
