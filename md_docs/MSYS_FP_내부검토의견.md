> **2026-07-20 추가** — 담당자 확인 결과, 데이터 수집은 **데이터 수집 파트가 Airflow로 수행**하며 그 상태를 공유 DB에 기록하고, **모니터링 파트(MSYS)는 이를 읽어 활용**하는 구조임이 확정되었습니다.

## 4. 제외 판단의 근거

### 4.1 코드성 데이터 및 유지 트랜잭션 (13건)

교육자료 L1454 *"하나의 트랜잭션 기능은 하나 이상의 데이터 기능을 참조한다"* 를 적용했습니다. 코드성 데이터는 산정 제외 대상이므로, 이를 유지하는 트랜잭션은 참조 데이터기능이 0개가 되어 식별규칙을 충족하지 못합니다.

| 데이터 | 제외 트랜잭션 |
|--------|-------------|
| `tb_icon` | `/icons/save` `/icons/delete` `/icons/toggle-display` `/icons/import` `/icons/all` `/icons/export` (6) |
| `tb_sts_cd_mst` | `/status_codes` `/status_codes/sync` `/status_codes/save` `/api/sts_cd/colors` (4) |
| `tb_menu` | 교육자료 L2810 적용 |

> **쟁점**: 관리자가 화면에서 실제로 아이콘·상태코드를 관리하고 있어, 개발 공수는 발생했습니다. 다만 교육자료 기준상 코드성 데이터로 분류되므로 제외했습니다. 평가 단계에서 이의가 제기될 수 있는 항목입니다. (최대 40.9 FP 차이)

### 4.2 화면 렌더링 (12건)

각 화면은 `render_template()`만 수행하고 데이터는 별도 `/api/` 엔드포인트가 담당하며, **해당 API는 모두 산정에 포함**되어 있습니다. 화면을 별도 산정하면 동일 단위기능의 중복 계상이 됩니다.

> **쟁점**: 교육자료 L2703은 *"해당화면에 대한 작업 공수 발생하므로 최저인 EQ로 산정 권고 / 또는 기능목록상으로만 관리"* 두 선택지를 제시합니다. 본 산정은 중복 방지를 우선해 후자를 적용했습니다. 전자를 적용하면 **+46.8 FP** 입니다.

```
500 FP   대입 → 1.2800  (교육자료 명시 경계값과 일치)
3,000 FP 대입 → 1.1530  (교육자료 명시 경계값과 일치)
550.7 FP 대입 → 1.2067  ← MSYS 적용
```

> 종전 문서는 500 FP 미만 기준인 **1.28을 그대로 적용**하고 있었습니다. MSYS는 550.7 FP로 구간 밖이므로 산식 계산이 필요합니다.

> 사내 지침의 보안성 계수는 "항목별 +0.05 가산" 방식으로 기재되어 있었으나, 교육자료 원본은 **요구사항 가짓수별 단계 적용** 방식입니다. 지침을 교육자료 기준으로 정정했습니다. (3가지 → 1.15가 아닌 **1.03**)
